## Принятые решения

1. **`class` вместо `data class`**:
   Выбраны обычные классы без `data`. В `data class` свойство `val teachers: List<String>` сохраняет переданную ссылку без защитного копирования, а автогенерируемый `copy()` усложняет защиту коллекций. В обычном `class` список копируется при создании (`Collections.unmodifiableList(teachers.toList())`), а метод `copy()` отсутствует в API, поэтому обойти инварианты через него невозможно.

2. **Почему в `AuditedSessionRepository` нельзя переопределить только `add`**:
   - При `SessionRepository by delegate` непереопределённый `addAll` вызывается напрямую у `delegate`, где вызовы не проходят через обёртку `AuditedSessionRepository`.
   - Даже если бы `addAll` вызывал `add` в цикле, создавалось бы `N` событий `"add"` по 1 занятию вместо одного события `"addAll"` с размером списка (а для пустого списка событие не создавалось бы вовсе).

3. **Что защищает модель в тестах 1–8**:
   - Отсутствие места и преподавателей у `Cancelled` и отсутствие `copy()` (п. 8) — **устройство типа**.
   - Пустая тема (п. 1), год вне `1..9999` (п. 2), пустой список преподавателей (п. 3), один преподаватель у сдачи (п. 4), дубликаты преподавателей (п. 5) — **проверка при создании (`init`)**.
   - Изменение входного списка (п. 6) и изменение выданного списка (п. 7) — **защита коллекции** (`toList()` + `unmodifiableList`).

4. **Сообщения для дополнительных ошибок (п. 7.1–7.6)**:
   - 7.1: `line N: control character in field "<field>": "<value>"`
   - 7.2: `line N: external whitespace in field "<field>": "<value>"`
   - 7.3: `line N: invalid cancelled field "<field>": "<value>"`
   - 7.4: `line N: invalid location "<value>"`
   - 7.5: `line N: invalid teacher "<value>"`
   - 7.6: `line N: duplicate teacher "<value>"`
